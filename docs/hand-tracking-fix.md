# 第 28 課手部追蹤修正與獨立網站範例庫

目前以 `examples/web` 為唯一正式範例庫，28 個 SB3 隨 Git 發布並用於部署。不再保留原始教材資料夾，也不需要來源轉換腳本。

## 範例維護

網站預設讀取專案內的 `examples/web`；未設定 SCRATCH_EXAMPLES_DIR 也可直接使用。更新教材後執行 `npm run examples:index` 更新 SHA-256 manifest，再提交 SB3 與 manifest。建置與載入都不會偷偷改寫教材。

## 根因與取捨

原版 Handpose 沒偵測到手時保留上次 landmarks。本地安全生命週期會清空過期結果，getX/getY 回傳空字串；原第 28 課沒有有效性判斷，直接四捨五入，空字串變成 0，再把紅點移到 (0,0)。原動作判斷也沒有每輪重設，所以失去手後可能仍保留「向右」。

本次沒有用「永遠保留舊座標」遮掩無手狀態，也沒有修改通用 VM 的數值轉換／移動規則。採用明確的有效性判斷，讓作品自行控制無手時的畫面與動作。

## 目前狀態：比賽相容（只用官方積木）

比賽使用官方 Handpose2Scratch 編輯器（champierre，ml5 0.12.2，與本站同一個模型），只能用官方的 6 個積木（x／y／z 座標、攝影機、視訊透明度、座標倍率）加上 Music、Pen。因此：

- **使用未修改的官方擴充**：`upstream/handpose2scratch.js` 原封不動安裝（與官方 install.sh 相同，ml5 0.12.2 由擴充自己 `require`）。因此積木為英文、載入作品時開啟相機並顯示官方提示、沒有偵測到手時保留最後座標；本站原有的相機按鈕、狀態列與「偵測到手？」積木都已移除。擴充庫提供比賽可用的 Music、Pen、Handpose2Scratch。
- **第 9–28 課都改用手勢判斷**（第 9 課加入握拳與手指朝上、第 10 課加入朝左、第 11 課起加入朝右；步驟課直接寫入 `動作`，第 28 課寫入 `手勢`），只讀手腕(1)、中指根部(10)、中指尖(13) 的 x／y：
  - `方向X/Y` ＝ 手腕→中指尖；`指尖距離` ＝ |方向X|+|方向Y|；`指根距離` ＝ 手腕→中指根部的同樣距離。
  - 握拳（指尖距離 < 指根距離 × 1.3）＝ 預備；手張開（> × 1.6）時，手指朝上（方向Y > |方向X|×1.5）＝舉高、朝左／朝右（|方向X| > |方向Y|×1.5）＝向左／向右；斜向與半握拳維持原手勢。
  - 用的是比例，與離鏡頭遠近、站在畫面哪裡無關；手不必大範圍移動，避開 handpose 最容易跟丟的快速移動與畫面邊緣。
  - 只判斷真正的手（指根距離 > 10）與新畫面（方向X 與上一輪不同）：官方會保留最後座標，若用舊座標重判，按 ↓ 後會被舊的手勢再觸發一次。
  - `鎖`／確認 0.15 秒／方向鍵維持原設計：每次握拳後只成立一個動作。紅點跟著手腕、一直顯示；預備區方框（位置用）隱藏；主持人開場提示改為手勢說明。
- **開場教學**：按綠旗後，主持人依序引導「手指朝上＝舉高 → 握拳＝預備 → 手指朝左 → 握拳 → 手指朝右 → 握拳」，每一步都等玩家真的做出手勢才繼續；做對方向時舞者會跳出該動作並播放音效。每一步都用一般積木寫成（比賽不能用自訂積木）：「如果 跳過教學 = 0」包住提示與「等待直到 動作 = 目標 或 跳過教學 = 1」；按空白鍵設定 `跳過教學`，剩下的步驟立即略過。完成或跳過後「手指朝上」開始遊戲。遊戲中「換你了！」也提醒先握拳。主持人的積木以 Scratch「整理積木」重新排列，修正原本「答對了」與「答錯了」兩段重疊。
- **版面**：主持人的對話框固定在左上方，所以第 22–28 課的「分數／連續答對／生命」移到左下角，第 20–25 課的「題目」清單移到右側（寬 90，不碰到舞者）；第 26–28 課封面的 CC 授權圖示縮小為 60% 並移到右下角（只在封面出現）；第 26–28 課的開場與教學提示改短，對話框較小。
- `tests/lesson-audit.test.ts` 檢查全部 28 課只用官方 Handpose 積木與 handpose2scratch／music／pen 擴充。

- 第 11–27 課的預備區（位置方框）隱藏；第 26、27 課開場提示、第 19 課起「換你了！」改為手勢說明。開場教學只在第 28 課。
- 第 14–27 課「AI偵測」、第 25–27 課與第 28 課「主持人」原本有積木串重疊，已以 Scratch「整理積木」重新排列；瀏覽器測試檢查全部 28 課每個角色的積木串都不重疊。
- 注意：各課舞台註解寫著「跟著教學網頁做」，教學網頁需同步改為手勢說明（第 9–11 課網頁標題原為「舉左手／舉右手／張開雙手」）。

以下各節記錄先前（位置判斷）的修正歷程。

## 修正

1. `handpose2scratch` 新增 Boolean reporter **偵測到手？**（`isHandDetected`）。既有 `getX/getY/getZ/setRatio`、參數與座標公式不變。
2. 一次只執行一個 predict；完成後在下一個 requestAnimationFrame 繼續，移除額外 100ms 延遲。停止取消 frame、清空 live landmarks，舊 generation 的非同步結果不能復活。
3. 第 28 課以 **偵測到手？** 判斷有效性，只在偵測到手時讀座標、移動並顯示紅點。
4. 第 28 課的動作判斷採「黏著＋遲滯」（第二版修正，見下節）：鏡頭結果存於 `手勢`；↓ 把 `手勢` 設回預備，接著 `動作 = 手勢`，再讓 ←→↑ 在按住時覆寫 `動作`。放開按鍵即回到 `手勢`，沒有手仍可用鍵盤。
5. 第 7–28 課全部改追蹤 **第 1 號（手腕）**（原為第 10 號中指根部）。手腕約比中指根部低 50（舞台座標），舉高與預備門檻隨之下移。比率仍為 0.75、鏡像語意不變。
6. 只調整 AI偵測與預備區角色的積木：新增防護分支、起始隱藏紅點，並將下方原有確認積木串下移，避免兩串重疊。其他角色、舞台、造型／音效資產全部未變。
7. 狀態列區分「單手辨識中」與「單手辨識中（未偵測到手）」。

這是實際保存於網站版 SB3 的積木修正，匯出會保留，不是載入時隱藏改寫 VM。由於新增 `isHandDetected`，修正版需在支援此 Boolean reporter 的本機編輯器執行；原版 Handpose 編輯器不認識此新增積木。正式教材就是 repo 中的修正版。

## 第二版：防止重複觸發（僅修改 SB3）

第一版每輪先把 `動作` 設回「預備」，Handpose 只要漏掉一幀，`鎖` 就會解開，手回來後同一個動作會再送一次「動作成立」，記憶題因此被判答錯。手在門檻附近抖動也有同樣效果。第 9–27 課原本是「黏著」寫法（只有手Y < -20 才回預備），沒有這個問題；第 28 課改回黏著並補上遲滯與寬限：

| 條件（舞台座標，手腕 1 號） | `手勢` |
|---|---|
| \|手X\| < 60 且 手Y < -35（預備區） | 預備 |
| 手X < -90 | 向左 |
| 手X > 90 | 向右 |
| 手Y > 40 | 舉高（最後判斷，優先） |
| 其他位置（死區） | 維持不變 |

- 門檻由 ±120／80 內縮，不必把手伸到 Handpose 最容易失手的畫面邊緣；與預備區之間保留 30（左右）與 75（上下）的緩衝。舉高需手腕明確高於畫面中線（約畫面上方 39%），手放在胸前等待不會誤判。
- 預備區角色縮為 50% 並移到 (0, -75)：方框為 x ±60、y -115～-35，上緣與左右剛好對齊判斷條件；比方框更低的位置也算預備。方框下緣與封面授權標示（含邊框線，上緣 y = -119）保持 4 的間距，不會遮住它，因此預備區一直可見，與第 11–27 課一致。
- 失手時只隱藏紅點：用 `計時器` 計算（`最後看到手`），超過 0.2 秒才隱藏紅點並清空手X/手Y。不能用迴圈次數計算，因為畫面沒重繪時 Scratch 會在一幀內重複執行 forever 迴圈很多次。
- 失手**不會**解鎖：`手勢` 保留到手回到預備區或按 ↓ 為止。手被畫面切掉、過一陣子在同一區重新出現，也不會再送一次同樣的動作。
- forever 迴圈最後加上「等待 0 秒」：它會要求重繪，讓 VM 每個畫面只跑一次迴圈。沒有手時紅點隱藏、沒有重繪，VM 原本會在每 33ms 中空轉約 25ms，搶走模型推論時間（實測推論由每秒 22 次回到 49 次）。
- 確認動作的等待由 0.2 秒縮短為 0.15 秒：抖動已由遲滯與死區過濾；保留 0.15 秒是為了斜向舉手時短暫經過左右區域不被誤判。

## 第 9–27 課（最小修正）

步驟課保留原本的黏著寫法、按 ↓ 回預備的鍵盤操作，以及無手時紅點回到 (0,0) 的原行為，只調整關節與門檻（與第 28 課相同）：

- 第 7–27 課：改追蹤手腕（第 1 號）。
- 第 9–27 課：手X < -120 → -90、手X > 120 → 90、手Y > 80 → 40（手腕）。
- 第 10–27 課：預備改為 `|手X| < 60 且 手Y < -35`；第 11–27 課另將預備區角色縮為 50% 並移到 (0, -75)，與判斷範圍一致。避免手放在下方左右角落、X 在門檻附近抖動時，在「向左／向右」與「預備」間來回切換而重複觸發。
- 第 10 課沒有預備區角色，改在預備判斷積木上附註解說明範圍，並預告第 11 課會加上方框。
- 第 15–27 課：確認動作的等待由 0.2 秒改為 0.15 秒（與第 28 課相同）。
- 第 28 課的「等待 0 秒」效能修正不需要：步驟課的紅點從不隱藏，每輪移動紅點本身就會要求重繪，VM 不會空轉。

## 調整門檻

手勢門檻集中在 `scripts/handpose-lessons.cjs` 的 `GESTURE`：`fist`（握拳比例，預設 1.3）、`open`（張開比例，1.6）、`direction`（方向需大於另一軸的倍數，1.5）、`minBase`（指根距離下限，10）、`confirm`（第 15 課起的確認時間，0.15 秒）。修改後執行 `npm run examples:handpose`（可重複執行，數值相同的檔案不會改寫；各課的手勢說明註解也會一起更新），再執行 `npm run examples:index` 並一起提交。測試讀取同一份設定，並檢查握拳與張開之間保留緩衝、方向保留斜向死區，以及每個 SB3 都與設定一致。

## 驗證內容

- 範例完整性測試會驗證全部 28 份 SB3 與 manifest SHA、SB3 結構及第 28 課的無手防護；另有 RAF 單一推論與 stop 後不復活測試。
- 瀏覽器使用真正 Scratch VM、完整第 28 課，注入可控的模型輸出：門檻附近抖動與短暫失手時 `動作` 全程不變、`鎖` 不解開；失手 0.2 秒隱藏紅點、長時間失手後在同一區重新出現不會再觸發；只有預備區或 ↓ 能解鎖，中間死區不會；方向鍵仍可用。
- 使用手勢啟動封面，再逐一回答第一回合的全部 3–5 個題目，確認實際加分。
- 匯出並重新匯入修正版，確認新增積木確實保留。
- 另有真正 ml5 模型下載及 fake video 推論測試；沒有把可控輸入當成真實手部辨識成功。
- 斜向舉手時短暫經過左側區（少於 0.15 秒確認時間）只會成立「舉高」。測試實際量測停留時間，頁面太忙使停留超過 110ms 時重試；把確認時間改成 0.05 秒會讓這項測試失敗。
- 新增積木後以實際 Blockly 的兩個頂層群組邊界檢查間距，防止與原有下方積木串重疊。
- `tests/lesson-audit.test.ts` 靜態檢查全部 28 課：素材 md5、積木上下連結、變數／清單／廣播 id、造型／背景／音效選單名稱、註解連結，以及每個廣播都有收發兩端。
- 瀏覽器在真正 VM 逐一載入 28 課，確認每個積木都有對應的 VM 指令、每個造型／音效素材都實際載入（不是缺檔替代圖）。

請重新整理網站，從「範例」重新載入第 28 課後按綠旗。實體手部的追蹤準確率仍須使用真實攝影機驗收。
