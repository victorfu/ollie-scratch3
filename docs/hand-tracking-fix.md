# 第 28 課手部追蹤修正與獨立網站範例庫

目前以 `examples/web` 為唯一正式範例庫，28 個 SB3 隨 Git 發布並用於部署。不再保留原始教材資料夾，也不需要來源轉換腳本。

## 範例維護

網站預設讀取專案內的 `examples/web`；未設定 SCRATCH_EXAMPLES_DIR 也可直接使用。更新教材後執行 `npm run examples:index` 更新 SHA-256 manifest，再提交 SB3 與 manifest。建置與載入都不會偷偷改寫教材。

## 根因與取捨

原版 Handpose 沒偵測到手時保留上次 landmarks。本地安全生命週期會清空過期結果，getX/getY 回傳空字串；原第 28 課沒有有效性判斷，直接四捨五入，空字串變成 0，再把紅點移到 (0,0)。原動作判斷也沒有每輪重設，所以失去手後可能仍保留「向右」。

本次沒有用「永遠保留舊座標」遮掩無手狀態，也沒有修改通用 VM 的數值轉換／移動規則。採用明確的有效性判斷，讓作品自行控制無手時的畫面與動作。

## 修正

1. `handpose2scratch` 新增 Boolean reporter **偵測到手？**（`isHandDetected`）。既有 `getX/getY/getZ/setRatio`、參數與座標公式不變。
2. 一次只執行一個 predict；完成後在下一個 requestAnimationFrame 繼續，移除額外 100ms 延遲。停止取消 frame、清空 live landmarks，舊 generation 的非同步結果不能復活。
3. 第 28 課以 **偵測到手？** 判斷有效性，只在偵測到手時讀座標、移動並顯示紅點。
4. 第 28 課的動作判斷採「黏著＋遲滯」（第二版修正，見下節）：鏡頭結果存於 `手勢`；↓ 把 `手勢` 設回預備，接著 `動作 = 手勢`，再讓 ←→↑ 在按住時覆寫 `動作`。放開按鍵即回到 `手勢`，沒有手仍可用鍵盤。
5. 關節仍為原檔的 **第 10 號（中指根部）**，沒有擅自改成第 1 號手腕。比率仍為 0.75、鏡像語意不變。
6. 只調整 AI偵測與預備區角色的積木：新增防護分支、起始隱藏紅點，並將下方原有確認積木串下移，避免兩串重疊。其他角色、舞台、造型／音效資產全部未變。
7. 狀態列區分「單手辨識中」與「單手辨識中（未偵測到手）」。

這是實際保存於網站版 SB3 的積木修正，匯出會保留，不是載入時隱藏改寫 VM。由於新增 `isHandDetected`，修正版需在支援此 Boolean reporter 的本機編輯器執行；原版 Handpose 編輯器不認識此新增積木。正式教材就是 repo 中的修正版。

## 第二版：防止重複觸發（僅修改 SB3）

第一版每輪先把 `動作` 設回「預備」，Handpose 只要漏掉一幀，`鎖` 就會解開，手回來後同一個動作會再送一次「動作成立」，記憶題因此被判答錯。手在門檻附近抖動也有同樣效果。第 9–27 課原本是「黏著」寫法（只有手Y < -20 才回預備），沒有這個問題；第 28 課改回黏著並補上遲滯與寬限：

| 條件（舞台座標，中指根部 10 號） | `手勢` |
|---|---|
| \|手X\| < 60 且 手Y < -20（預備區） | 預備 |
| 手X < -90 | 向左 |
| 手X > 90 | 向右 |
| 手Y > 50 | 舉高（最後判斷，優先） |
| 其他位置（死區） | 維持不變 |

- 門檻由 ±120／80 內縮，不必把手伸到 Handpose 最容易失手的畫面邊緣；與預備區之間保留 30（左右）與 70（上下）的緩衝。
- 預備區角色縮為 50% 並移到 (0, -60)：方框為 x ±60、y -100～-20，上緣與左右剛好對齊判斷條件；比方框更低的位置也算預備。
- 失手時只隱藏紅點：用 `計時器` 計算（`最後看到手`），超過 0.2 秒才隱藏紅點並清空手X/手Y。不能用迴圈次數計算，因為畫面沒重繪時 Scratch 會在一幀內重複執行 forever 迴圈很多次。
- 失手**不會**解鎖：`手勢` 保留到手回到預備區或按 ↓ 為止。手被畫面切掉、過一陣子在同一區重新出現，也不會再送一次同樣的動作。

## 第 9–27 課（最小修正）

步驟課保留原本的黏著寫法、按 ↓ 回預備的鍵盤操作，以及無手時紅點回到 (0,0) 的原行為，只調整門檻：

- 第 9–27 課：手X < -120 → -90、手X > 120 → 90、手Y > 80 → 50。
- 第 10–27 課：預備改為 `|手X| < 60 且 手Y < -20`；第 11–27 課另將預備區角色縮為 50% 並移到 (0, -60)，與判斷範圍一致。避免手放在下方左右角落、X 在門檻附近抖動時，在「向左／向右」與「預備」間來回切換而重複觸發。
- 第 10 課沒有預備區角色，改在預備判斷積木上附註解說明範圍，並預告第 11 課會加上方框。

## 調整門檻

門檻數值集中在 `scripts/handpose-lessons.cjs` 的 `ZONES`。修改後執行 `npm run examples:handpose`（可重複執行，數值相同的檔案不會改寫），再執行 `npm run examples:index` 並一起提交。此腳本只改數值，不改積木結構。

## 驗證內容

- 範例完整性測試會驗證全部 28 份 SB3 與 manifest SHA、SB3 結構及第 28 課的無手防護；另有 RAF 單一推論與 stop 後不復活測試。
- 瀏覽器使用真正 Scratch VM、完整第 28 課，注入可控的模型輸出：門檻附近抖動與短暫失手時 `動作` 全程不變、`鎖` 不解開；失手 0.2 秒隱藏紅點、長時間失手後在同一區重新出現不會再觸發；只有預備區或 ↓ 能解鎖，中間死區不會；方向鍵仍可用。
- 使用手勢啟動封面，再逐一回答第一回合的全部 3–5 個題目，確認實際加分。
- 匯出並重新匯入修正版，確認新增積木確實保留。
- 另有真正 ml5 模型下載及 fake video 推論測試；沒有把可控輸入當成真實手部辨識成功。
- 新增積木後以實際 Blockly 的兩個頂層群組邊界檢查間距，防止與原有下方積木串重疊。
- `tests/lesson-audit.test.ts` 靜態檢查全部 28 課：素材 md5、積木上下連結、變數／清單／廣播 id、造型／背景／音效選單名稱、註解連結，以及每個廣播都有收發兩端。
- 瀏覽器在真正 VM 逐一載入 28 課，確認每個積木都有對應的 VM 指令、每個造型／音效素材都實際載入（不是缺檔替代圖）。

請重新整理網站，從「範例」重新載入第 28 課後按綠旗。實體手部的追蹤準確率仍須使用真實攝影機驗收。
